# Project generator

`src/utils/project.ts` turns the editor's component tree into a complete, runnable project. It is step 1 of publishing: the output is a map of file path to file content. Writing the files, building and starting the app come later (the deploy service).

## What it does

```ts
const files = await generateProject(components, {
  name: 'my-app',
  basePath: '/apps/<appId>',          // optional
  npmRegistry: 'https://artifactory…', // optional
})
```

`components` is the editor's `IComponents` map (flat, keyed by id). The function reuses `generateCode` from `src/utils/code.ts` for the React code, and adds everything needed to run it.

## Generated files

| File | Purpose |
|---|---|
| `package.json` | React 18, Chakra UI v2, Vite. Scripts: `dev`, `build`, `start` |
| `.npmrc` | Points npm at the private registry when `npmRegistry` is given |
| `vite.config.js` | `base` is read from `process.env.BASE_PATH` |
| `index.html`, `src/main.jsx` | App entry point |
| `src/App.jsx` | The user's design, generated by `generateCode` |
| `server.js` | Dependency-free static server for `dist/` |
| `.env.build` | `BASE_PATH=<basePath>`, read by the deployer |

## Rules that keep generated code unchanged

- **Base path and port never appear in generated code.** `BASE_PATH` is set when running `vite build`. `PORT` and `BASE_PATH` are read by `server.js` at start-up. The same project can be deployed on any VM, port or URL path without edits.
- **Registry is configuration, not code.** The Artifactory URL only goes into `.npmrc`.
- **Reproducibility:** the output has no lockfile. The deployer runs `npm install` once at build time and keeps the resulting `package-lock.json` with the release.

## Publishing (implemented)

`POST /api/publish` (`src/pages/api/publish.ts`) calls `publish()` in `src/server/publisher.ts`. The editor's **Publish** button (header, replaces the CodeSandbox export) calls it.

Request body: `{ components, appId, ait? }`. `appId` and `ait` must be 3-40 characters of lowercase letters, digits and dashes. `ait` defaults to `DEFAULT_AIT`, then `default`.

The start, health-check, port and registry code lives in `runtime/lifecycle.js`, shared with the reconciler.

Steps, in order:

1. **Release number:** the next integer under `<shared>/apps/<ait>/<appId>/releases/`.
2. **Generate:** `generateProject` writes the files into a **local** build directory, not the shared volume.
3. **Install and build:** `npm install --include=dev`, then `npm run build` with `BASE_PATH=/apps/<appId>`. This happens on local disk because installing thousands of small files over NFS/EFS is slow. `--include=dev` is needed because the builder itself runs with `NODE_ENV=production`, which would otherwise skip Vite.
4. **Copy to the shared release:** only `dist/`, `server.js`, `package.json`, `package-lock.json` and `.env.build`. There is no `node_modules` on the shared volume.
5. **Allocate a port:** the first port in `PORT_MIN`-`PORT_MAX` that is free on this VM (checked by binding) and not already claimed by a registry entry for this VM.
6. **Start:** `node server.js` in the release directory with `PORT` and `BASE_PATH` set, detached, logging to `app.log`.
7. **Health check:** polls `/healthz` for up to 15 seconds. On failure the new process is stopped and nothing is registered.
8. **Register:** writes `<shared>/registry/<appId>.json` atomically (temp file plus rename).
9. **Retire the old release:** if the previous registry entry is on this VM, its process is stopped. Registration happens first, so the app is never without a running release.

Response: `{ appId, release, url, directUrl, entry }`.

- `url` is `PUBLIC_BASE_URL/apps/<appId>/`, the stable URL served by the proxy (see `proxy.md`). It is a relative path if `PUBLIC_BASE_URL` is empty.
- `directUrl` is `http://<VM_IP>:<port>/apps/<appId>/`. The Publish button links to this when `url` is not absolute.

Errors: `400` invalid id, `409` the same app is already being published, `503` no free port, `502` the app never became healthy, `500` install or build failure (with npm's stderr).

### Registry entry

```json
{
  "appId": "demo-app", "ait": "ait-1", "release": 2,
  "vm": "vm-test", "ip": "127.0.0.1", "port": 21001, "pid": 16877,
  "status": "running", "basePath": "/apps/demo-app",
  "updatedAt": "2026-11-03T07:14:41.842Z"
}
```

### Configuration

All environment-specific values are environment variables, so the same code runs on every VM.

| Variable | Default | Meaning |
|---|---|---|
| `SHARED_DIR` | `./.shared` | Shared volume root (`apps/`, `registry/`) |
| `BUILD_DIR` | OS temp dir + `builder-builds` | Local disk for install and build |
| `NPM_REGISTRY` | npm default | Private registry written into the generated `.npmrc` |
| `PORT_MIN`, `PORT_MAX` | `20000`, `20999` | Port range for this VM |
| `VM_NAME` | hostname | Registry key for this VM |
| `VM_IP` | `127.0.0.1` | Address other VMs use to reach this VM |
| `PUBLIC_BASE_URL` | empty | Host of the proxy, for the stable URL |
| `DEFAULT_AIT` | `default` | AIT used when the request has none |

## Other changes to the editor

- The CodeSandbox export (`src/utils/codesandbox.ts` and the `codesandbox` dependency) is removed, because it posted to an external service.
- Bugsnag reporting is disabled (`notifyReleaseStages: []`, key set to `disabled` in `.env`).
- `next.config.js` sets `typescript.ignoreBuildErrors` because of a `react-dnd` type clash with React 18.

## Verified

- `src/utils/project.test.ts` checks the file list, that `basePath` and the registry stay out of `App.jsx`, and the package name.
- End to end against a production build of the editor (`next build`, `next start`), with the shared directory and ports set through the environment variables above:
  - Publishing `demo-app` returned release 1 on port 21000.
  - Publishing it again returned release 2 on port 21001, and release 1's process was stopped.
  - The registry pointed at release 2, and `GET /apps/demo-app/` and `/healthz` on that port returned 200.
  - An invalid `appId` returned 400.

## Current limits

- **Frontend only:** the generated app is Vite and React. Next.js and Express scaffolds are not implemented yet.
- **Stable URL needs the proxy:** `url` only works when the proxy (`proxy.md`) is running and `PUBLIC_BASE_URL` points at it. Otherwise the Publish button falls back to `directUrl`.
- **No AIT identity:** the app runs as the user running the builder. Running under the AIT's service ID and UNIX group is not implemented.
- **Same-VM start only:** the builder starts the app on the VM that received the request. Retiring an old release only works when it was on the same VM.
- **Recovery is the reconciler's job:** the publisher only starts the app once. Restarts and moving apps off a lost VM are in `reconciler.md`.
- **Port race:** a port is checked, then used a moment later. Two simultaneous publishes on one VM could pick the same port. The second would fail its health check and report an error.
- **No auth:** `/api/publish` has no authentication. It builds and runs arbitrary generated code, so it must not be exposed beyond the bank network.
- `generateCode` is unchanged, so only what OpenChakra's Chakra components can express is covered. `server.js` has no caching headers or compression.
